# Precedents for the after-run labels

*Drafted by Claude, 2026-10-15, for the author's review; fixed when the author attests
the preregistration, before any run (README, choice 4).*

Claude labels the after-run half of the key. Where a case is of a kind the author
settled in the first test, Claude applies his ruling as the author's label and
cites it by the number below. A case that fits none of them is a new kind:
The author labels it, independently. The author also spot-checks a random tenth of the
labels applied by precedent, and how many he would change is reported.

The rulings come from the first test's key (`../scripted/answer-key.md`,
coding rules 1–15) and from the author's labeling sample, where he coded 20 of the
111 after-run items and settled each disagreement
(`../scripted/labels/sample-comparison.md`). Rules 9 and 10 of the fixed
reader (instructions and set-aside turns) are new, so cases under them are
new kinds the first time they arise.

## Calls

| # | Ruling | From |
| :- | :- | :- |
| P1 | An open request ("pick whatever approach you think is best") hands over every call needed to fulfill it: given, not taken. | Rule 1 |
| P2 | Taken is a call outside what was asked: an extra analysis, check, or piece of content the request didn't need. | Rule 1; item 9 |
| P3 | A call written out in text the author supplied is kept, as long as the finished work uses it as written. A call the author's question or notes only point toward, such as how to measure a construct the question names, is given. | Rules 2, 14; items 8, 18 |
| P4 | A reference list alone keeps the literature, not the citing: which source backs which claim is given, unless the author's text sets it. Claude citing a source for something the author's text doesn't is taken. | Rule 3; items 9, 17 |
| P5 | A call handed over and then overridden by the author is given, then changed. | Rule 4 |
| P6 | Accepting without a reason is okayed, for one call or a whole list ("Keep them"). | Rule 5 |
| P7 | A reason counts only for the calls it's about: "Keep X, because… Keep the rest" makes X elaborated and okayed and the rest okayed. | Rule 13; item 17 |
| P8 | A reply that mentions a call, even in passing, or an item on Claude's list of decisions, tells the author about it: ignored if the author never responds, okayed if the author accepts the list. | Rule 12; items 1, 11, 18 |
| P9 | A call no reply ever mentioned is wasn't notified. | Rule 12 |
| P10 | A bare `/attest` is a signed save, not a response: it neither okays a call nor confirms a check. | Rule 15 |
| P11 | A robustness check Claude picks inside a request for the analysis is given, not taken. | Item 11 |

## Claims

| # | Ruling | From |
| :- | :- | :- |
| P12 | An unchecked claim that is the author's, or part of what the author asked for, is no check. Wasn't notified applies only to a claim Claude added beyond what was asked (it belongs to a taken call) that no reply mentioned. | Rule 11; items 2–7, 12–16 |
| P13 | A check counts only if the record shows it: a tool call that compares the claim with its source or looks the source up. | Rule 9 |
| P14 | The author confirms a tool's check by responding to the reply that reported it, specifically or generally ("I've read the results", "Looks good"). | Rule 10 |
| P15 | A table counts once for its numbers and takes the weakest code of any part of it; a number in the text counts on its own. | Rule 6 |
| P16 | An `/attest` sentence counts only for the claims it names. | Rule 9 of the reader's instructions |
| P17 | When several codes apply, the strongest counts (except tables, P15). | Rule 8 |
