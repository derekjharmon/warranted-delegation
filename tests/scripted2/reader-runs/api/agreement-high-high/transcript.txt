+*Written before I built anything.*

+## What κ is
+
+Cohen's κ (Cohen, 1960) corrects percent agreement for the agreement two
+coders would reach by chance alone. It runs from 0, agreement no better than
+chance, to 1, perfect agreement. Landis and Koch (1977) call any κ above
+0.60 "almost perfect" agreement. Hallgren (2012) is a practical tutorial on
+computing κ and related statistics for observational data.
+
+## The example
+
+On example.csv, the two coders agree on 75 percent of the items, and κ is
+0.71.
+
+## Missing codes
+
+Rows where either coder left the code blank count as disagreements.

## Decided by the methods-kit tool-conventions skill

Both rules are yours. These are my readings of them:

4. **Spaces are not stripped from codes.** I read "never recode" strictly, so `"conflict "` and `"conflict"` are different codes.
5. **Only an exactly empty cell counts as blank.** A cell holding a space is a code. This follows from 4.
6. **A UTF-8 byte-order mark at the start of the file is accepted.** Excel often adds one when it saves CSV, and it would otherwise become part of the `item` column name. I don't count this as recoding, because it's part of the file's encoding, not a code.

## Decisions in the tool

17. **The file is `agree.py`, at the project root.** Your spec names it but not where it goes.
18. **Columns are found by header name.** Extra columns are ignored and column order doesn't matter. Real files often carry note columns.
19. **A repeated item ID is an error.** It probably means a copy-paste mistake, and counting both rows would inflate agreement.
20. **A row with too few or too many fields is an error,** and so is broken CSV. I turned on strict parsing because Python's default silently accepts an unclosed quote. Silently misreading a row is worse than stopping.
21. **The file must be UTF-8.** Other encodings stop with an error instead of being guessed, because guessing could change codes.
22. **Exit code 1 for my errors, but argparse's own usage errors (e.g. no file given) exit with 2.** That inconsistency is argparse's default and I left it. I can make them match if you want.
23. **A file with no complete rows is an error;** with no rows there's nothing to report.
24. **An undefined κ is reported as `null`, not as an error.** This happens when both coders give every item the same single code. Percent agreement (100%) is still meaningful then. The check is an exact `== 1` comparison, which is safe here because that case gives exactly 1.
25. **The output fields:**
    - `n_items` and `n_excluded`, so the exclusion is visible.
    - `categories`, sorted by Python's default string order (uppercase before lowercase), so you can spot near-duplicate codes.
    - Percent agreement on a 0–100 scale, not as a proportion, to match the name.
    - Numbers are not rounded, since rounding is the reader's job.
    - The JSON is indented, for readability.

    Not included: standard errors, confidence intervals, weighted κ, a cross-table, or any options. You didn't ask for them.
26. **Unchecked inputs:** blank lines are skipped (the CSV reader's default), and empty item IDs are allowed.
