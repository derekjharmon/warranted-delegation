**My decision:** keep the pooled Poisson estimates, switch to robust (sandwich) standard errors, and add a worst-case bound on the standard errors for repeated people. Don't try to rebuild person IDs.

**Why the estimates themselves are fine.** Pooled Poisson gives consistent rate ratios even when the same person's years are correlated. All it needs is the right model for the expected visit count. Repeated people only cause a problem for the standard errors and p-values, not for the IRRs in Table 1.

**Why the standard errors need two fixes:**
1. **Overdispersion (χ²/df ≈ 6.3).** Robust standard errors fix this fully, and they don't require a person ID. This should be the main specification.
2. **The same people across years.** Robust standard errors don't fix this, because they still treat every row as independent. It matters most for the treatment variables. As I understand it, the experiment assigned people (by family) to a plan for their whole enrollment, so `lncoins` and `idp` don't change from year to year for a person. When a variable is constant within each person, ignoring repeated people understates its standard error the most. In fact, assignment was by family, so the ideal clustering would be by family, which we can't do either.

**How to handle the missing ID:**
- **Don't rebuild IDs from repeated covariate patterns.** Health status and chronic disease counts change over time, and many different people share the same values, so any matching would be guesswork posing as data.
- **Report a worst-case bound.** Inferring from the experiment's design (my assumption, not checked), the 20,190 person-years probably come from roughly 3–4 years per person. If a person's years were perfectly correlated, the standard errors would grow by about √(years per person), roughly 1.8–2×. I'd report each treatment test with the robust standard error multiplied by that factor. If `lncoins` and `idp` still pass at .05 two-tailed in that worst case, the conclusion doesn't depend on the missing ID. The current z-statistics are huge (p ~ 1e-225), so I expect they will, but that's a prediction, not a result.
- **Better, if you can:** get a version of the RAND HIE data that includes person and family IDs and cluster by family. I believe some public copies have them, but I haven't checked.

**One process point.** This is a change to the inference made after seeing Table 1. To keep the pre-analysis plan honest, I'd add a dated "Deviations" section to `plan.md` rather than edit the original model section, explaining that the robust standard errors and the bound were added because of the overdispersion and the missing person ID.
