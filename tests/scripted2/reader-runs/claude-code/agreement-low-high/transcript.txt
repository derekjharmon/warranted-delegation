Here's what I propose for each case. In all of them the tool writes nothing to stdout when it fails, so a downstream program never reads a half-finished result.

**1. A required column is missing**
- **Proposal:** stop with an error on stderr and exit 1. The message should name the missing columns and list the ones it found, e.g. `missing column(s): coder2; found: item, coder1, coder_2`.

- Extra columns are ignored, so people can keep notes columns in their files.
- An empty file, or one with no header row, gets the same error.

**2. Only one category in the data**
There are two different situations here:
- **Both coders used the same single category for every item.** Agreement is 100%, but chance agreement is also 1, so κ is 0/0 and undefined. **Proposal:** still report percent agreement and the dropped count, set `"kappa": null` in the JSON, print a warning on stderr explaining why, and exit 0. Percent agreement is still a true and useful number. Making the whole run an error would throw it away, and reporting κ as 0 or 1 would be wrong.
- **One coder used a single category and the other used several.** κ is well defined here and comes out at exactly 0. **Proposal:** report it as is. It's a real result: knowing coder 1's codes tells you nothing about coder 2's. The function already handles this.

The function currently raises an error in the first situation. I'd change it to return `None` for κ so the reporting layer can decide what to show.

**3. Fewer than two rows left after dropping blanks**
- **Proposal:** stop with an error on stderr and exit 1. The message should give the counts, e.g. `only 1 row left to compare (5 read, 4 dropped for blank codes); need at least 2`. The counts tell the user whether the file was short or mostly blank.
- With zero rows, nothing can be computed.
- With one row, both statistics can technically be computed. Percent agreement is 0 or 100. κ is undefined if the two codes match and exactly 0 if they don't. Neither number tells you anything about agreement, so I'd refuse rather than print something that looks like a finding.
- This check runs before the single-category check, so a single matching row gets this error rather than the `null` κ from case 2.

# agree.py
One sentence: computes percent agreement and unweighted Cohen's κ for two coders who coded the same items, and prints the results as JSON.

## What it computes
Percent agreement, and Cohen's (1960) κ as (p_o − p_e) / (1 − p_e), unweighted. This should say κ can be negative, which happens when the coders agree less often than chance would predict. If you cite Landis and Koch, give their labels correctly: 0.61–0.80 is "substantial".

## Requirements
Python 3 and nothing else. The tool and its tests use only the standard library.

## Usage
The command `python3 agree.py FILE.csv`, plus a note that `--help` lists the options.

## Input
